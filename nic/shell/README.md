# NIC static shell

The NIC static shell is the patched SLASH 1.0.0 service shell (m05) with the
CPM5 QDMA streaming interfaces wired into the service-layer partition. It is
written to flash partition 0 of the V80. Partition 1 belongs to another
project and is not touched.

## Files

- `patch_shell.py <slashkit dir>` applies the changes to a clean slashkit
  tree. That tree is the m05 one: the NoC route patch in `top.tcl` and the
  `versal_sdt` fix in `aved/plm/build-plm.sh`. The script refuses a tree it
  has already patched. `NIC_DMA_MHZ` sets the DMA clock (default 390).
- `rtl/qdma_noc_bridge.v`: the static cell on the CIPS dma1 streaming ports,
  `qdma_st_pipe` (registered stages next to the CPM) and `qdma_noc_static`
  (framing, split/merge over the NoC ports, c2h CRC and ECC, events, irq).
- `rtl/qdma_noc_rm.v`: the RM-side counterpart, for logic in the service
  layer. `rtl/qdma_noc_rm_stub.v`: the default RM's tie-off.
- `rtl/qnoc_lib.v` (skid buffer, FIFO), `rtl/qnoc_crc512.v` (generated by
  `rtl/gen_qnoc_crc.py`), `rtl/qnoc_ecc57.v` (c2h control ECC).
- `sim/run_tb_qdma_noc.sh <work dir> [stress|perf]`: end-to-end xsim test,
  CPM model, both adapters, a NoC model with random latency, stalls and a
  16 GB/s cap per port, and the RM user side. `sim/run_tb_qdma_st_pipe.sh`
  tests `qdma_st_pipe` alone.
- `run_nic_shell.sh [jobs]` runs the full build on afrodita: slashkit
  install, all stages, in a memory-capped scope with a watchdog.
  `resume_nic_shell.sh` finishes a run whose parent Vivado died or whose
  timing failed.

## What changes against m05

| Where | Change |
|---|---|
| CIPS CPM | `CPM_PCIE1_DMA_INTF AXI_MM_and_AXI_Stream`: QDMA streaming with internal descriptors, no bypass |
| CIPS CPM | slave-bridge region 0 (CPM `axibar2pciebar_new_2`, AXI `0xE800_0000`): 128 MB in 64 × 2 MB windows, BDF entries 0–63. The m05 static had 4 KB with 1 window |
| CIPS CPM, address map | `NIC_BDF_BAR=1` (default): PF1 BAR2 enabled as a 16 KiB window translated to AXI `0xFCEA_0000` (CPM5_DMA1_CSR, BDF table at `0x2420 + 0x20 × i`), and the CPM register segment `psv_cpm` (`0xFC00_0000`, 16 MiB) assigned for `CPM_PCIE_NOC_0/1` instead of excluded, so the host can write the BDF table. Not yet built or tested; `NIC_BDF_BAR=0` gives the tested static |
| aved | `dma_clk_wiz` MMCM `pl2_ref_clk` 250 → 390 MHz. The CIPS PL reference clocks stop at 350 MHz on this part. 433.333 MHz failed: −0.228 ns inside the CPM's soft QDMA streaming logic, and the CPM user-clock input needs a period of at least 2.309 ns. 400 MHz failed by 25 ps and 390 MHz by 103 ps (direct partition pins) in the same logic. The MMCM output takes `pl2_ref_clk`'s place on the stock net: `dma1_intrfc_clk`, `hw_discovery` `aclk_pcie` and `pcie_psr`. `pcie_psr` now waits for the MMCM lock |
| aved | `qdma_noc_bridge` on the CIPS ports; `axis_noc` cells `qnoc_nmu` (h2c0, h2c1, evt) and `qnoc_nsu` (c2h0, c2h1, cmpt, cmd) on the DMA clock |
| static_region, top | the 7 INIs passed through to the service_layer container |
| build_project.tcl | impl_1 gets a post-route `phys_opt_design -directive AggressiveExplore` |
| service_layer (default RM) | the INI ports below, `axis_noc` endpoints, `qdma_noc_rm_stub` |
| constraints/impl.xdc | `pblock_service_layer` gets NoC NMU512 sites X1Y4–X3Y4 and X2Y9–X2Y10, 22 → 27 sites |

PG347 gives the Gen5x8 DMA clock range on -2MHP as 366–433 MHz, and AMD
marks the -2 rows "not recommended for performance". At 512 bits ×
390 MHz the raw rate is 199.7 Gb/s (24.96 GB/s) per direction.

## QDMA streams over the NoC

The CPM5 streaming interfaces exist only as PL ports, so the static takes
them next to the CPM and carries them over the NoC into the service layer,
the way SLASH carries the DCMAC streams. The partition boundary is 7 INIs,
not a thousand-odd partition pins, and the RM can use any clock.

What the NoC allows, checked with the 2025.1 NoC compiler (axis_noc,
`sim/noctest` probes on afrodita):

- one AXIS port carries at most 16000 MB/s; 25000 MB/s on one port is
  rejected. Each data direction therefore uses two 512-bit ports at
  12500 MB/s, and the beats of the stream alternate strictly between them
  (beat k on port k mod 2, one counter across packets). Each port delivers in
  order, so the receiver merges by the same rule.
- an AXIS NoC port has tdata, tkeep, tlast, tdest only. TUSER and TID can be
  set as properties but have no pins (the NMU's WUSER is tied to 0), so the
  CPM sidebands travel in-band.
- each stream into the NoC needs its own NMU512 site inside the source's
  pblock. The stock service pblock has 22 and SLASH's default RM already uses
  21 (8 DCMAC INIS, 8 `sl2noc`, 4 `noc_virt`, the slave bridge). The four
  QNOC streams out of the RM make 25, so `impl.xdc` adds row Y4 of NoC
  columns X1–X3 and X2Y9–X2Y10, 27 sites. With exactly 25 the NoC placer
  could not seat four `sl2noc` NMUs: an NMU has to be near where its driver
  is placed, and row Y4 is at the bottom of the region. An RM has at most
  2 NMUs beyond the 25 interface ones, and probably fewer in practice.

| RM port | Direction | Width | Reserved | Carries |
|---|---|---|---|---|
| `S_QNOC_H2C0`, `S_QNOC_H2C1` | static → RM | 512 | 12500 MB/s each | h2c data beats, then one trailer per packet |
| `S_QNOC_EVT` | static → RM | 256 | 4000 MB/s | c2h status, descriptor status, queue status, irq ack/fail |
| `M_QNOC_C2H0`, `M_QNOC_C2H1` | RM → static | 512 | 12500 MB/s each | one header per packet, then c2h data beats |
| `M_QNOC_CMPT` | RM → static | 512 | 8000 MB/s | completions: one beat up to 32 B, two for 64 B |
| `M_QNOC_CMD` | RM → static | 256 | 1000 MB/s | descriptor credits, irq requests |

Bit layouts are in the header of `rtl/qdma_noc_static.v`. Notes:

- **h2c trailer, not header:** PG347 lets `err` rise in the middle of a
  packet and keeps it to tlast, so the per-packet fields are only final at
  the end. The RM sees them on the tlast beat (`qdma_noc_rm`).
- **c2h:** the RM gives len, qid, port_id, marker, has_cmpt on the first
  beat. The static derives mty from len, computes the packet CRC (CRC-32
  0x04C11DB7 over the packet, MSB first, empty bytes zero, seeded with ones,
  as the CPM5 example design does) and the control ECC. The ECC matrix was
  measured in xsim from the example design's encoder, and the testbench
  checks every beat against that encoder.
- **Status channels** cannot be held: the static ties `tm_dsc_sts_rdy` and
  `qsts_out_rdy` to 1 (PG347; with `rdy` low, the first 400 MHz image, every
  context command hung: `IND_CTXT_CMD` busy, "init ctxt write failed" -16).
  Events pass through a 32-deep FIFO; when it is full they are dropped and a
  sticky overflow bit is set in every later event.
- **User interrupts:** the RM raises `valid` with `vec`/`fnc` stable, keeps
  it until `ack` or `fail` (a one-cycle pulse), then drops it for at least a
  cycle. The static runs the CPM handshake and returns the answer as an
  event.
- **Rates** (`sim/run_tb_qdma_noc.sh perf`, NoC ports capped at 16 GB/s):
  4 KB packets 25.0 GB/s both directions (one beat every DMA cycle), 64 B
  packets 250 Mpps both directions (two NoC beats per packet).

## Host side

PF1 (`10ee:50c1`) is the QDMA function: DMA BAR0 512 KB, 8 MSI-X vectors. The
AMD QDMA Linux driver and the DPDK QDMA PMD need `50c1` added to their device
tables.

Card → host through the slave bridge: the AXI window `0xE800_0000 +
n × 2 MB` (n = 0..63) maps through BDF entry n (`CPM5_DMA1_CSR 0xFCEA_2420 +
0x20 × n`), which is written from the PMC side.
